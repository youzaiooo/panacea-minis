# Health Wiki Record Maintenance

Panacea 私人健康 Wiki（默认 `/var/minis/memory/panacea-wiki`）的**记录维护机制**。
营养估算与数据源规则在 `health-coach`；医学证据规则在 `panacea`；本 Skill 只管「怎么把一条事件完整、可复核地落进 Wiki」。

## 一次事件的完整动作集（少一项即未完成）

先判事件类型，再按对应清单一次做完；做完当轮就要能回答「改过哪些文件」。

| 事件 | 必须产出 |
| --- | --- |
| 餐食/饮品上报 | `records/meals/YYYY-MM-DD-HHMM-*.md`；`records/daily/YYYY-MM-DD.md`（**升版本号**，旧口径保留并注明"已被 vN 取代"）；`index.md` 条目；`log.md` 新条目（**放最前**）；页数 |
| 体重/围度测量 | `records/measurements/` 独立记录；`profile.md` 基线行；`nutrition-goals.md` 目标表「当前」列；当日 `records/daily/` 头部；概念页「相关记录」互链；`index.md`；页数 |
| 产品（实物标签或商品页截图） | `concepts/foods/<slug>.md`；`concepts/food-database.md` 行 + 产品总数；`index.md` 产品条；产品页文件数；`dietary-profile.md` 库存行（在家常备品） |
| 用户更正既有记录 | 原地 patch（不删原文，未食用项加删除线）；重算当日累计并翻转状态旗标；必要时升版本 |
| 营养/医学知识问答（结论日后可复用） | `concepts/<slug>.md`（结论 + 证据与置信度 + 指向既有页的互链）；**证据原文抓取件存 `raw/sources/`**（官网抓空时记录实际用的镜像/替代来源）；相关既有页（产品页/索引段）补一条互链；`index.md` 条目；`log.md` 新条目；页数 |

- **一句话多事件必须拆档**：一句话里既有食物又有体重/症状时，分别落到 meals / measurements / symptoms，不能只建一个档。
- 日期用本地日期（`date` 实测），不要凭对话推断；进食/服用时间未知时用消息时间并标 provisional。

## Markdown 表格与索引的编辑机械坑

- **往表格插行：`old_string` 必须是「整行含行尾换行」，`new_string` = 原整行 + 新行。** 用行首片段做
  `old_string` 会截断该行剩余单元格、把两行内容串成一行（本会话因此损坏了库存表一行）。**表格改完必须
  读回该行区间逐行核对**——diff 摘要显示"已替换"，看不出串行。
- **页数/产品数一律「数文件」，不要 `grep -c` 索引页**：
  页面 `find . -name '*.md' -not -path './raw/*' | wc -l`；产品 `ls concepts/foods/*.md | wc -l`。
  索引页头部说明文字自身含 `concepts/foods/`，grep 会多算 1。
- 在大文件末尾追加（log.md 除外）要确认文件是**新增在最前**还是最后：`log.md` 为倒序，新条目插在标题块之后、
  上一条之前。

## 来源分级与「未标示」的处置

- **实物包装标签 = 一级来源**；**电商「商品参数/详情」页截图 = 二级来源**。二级来源也要建档，但产品页
  开头必须写**来源等级 + 验证状态表**：截图可见项 ✅；未显示项（生产商/委托方、SC 生产许可证、执行标准、
  条形码、净含量、贮存条件）❌ 并列入待补；固定一句「**实物标签优先，用户补拍则升版（v2）**」。
- 营销语与声称（「无添加蔗糖」「0 反式脂肪酸」「减胆固醇」）**只作记录、不作证据**。
- 中国标签强制项仅 1+4（能量 + 蛋白/脂肪/碳水/钠）→ **饱和脂肪与膳食纤维未标示属合规缺失，不等于 0**。
  用权威库折算并**输出区间而非单点**，标 low–medium：`同类 USDA FDC 条目的 SFA/脂肪比值 × 本品脂肪`；
  配料含乳脂（黄油/全脂乳粉）时另按乳脂 SFA 约占其脂肪 60–65% 给上限。
- 用户口述的产品名与既有产品页不同（如「豆奶」vs「豆浆」）**不得静默等同**：以既有产品页代用时标
  `product identity: medium（待确认）`，同时给出「若为小规格/别款」的替用数值，并请用户补产品名 + 净含量。
- 数据源缺口（如某来源返回 0）要在记录里写清「缺口 + 折算方法 + 置信度」，不要静默填数。

## 份量与测量条件的基准

- 用户报生鲜克重而未说明带皮/去皮、生重/熟重时，**先查本 Wiki 既有口径**（`dietary-profile.md` 与既往
  meal records）并沿用；在 Uncertainty 写明这次用的是哪一种，并给出另一口径下的数值区间。
- 换基准（例：改报去皮净重）必须**重算该笔并标版本**，不得静默替换已落账的数值。
- 用户**主动说明**的测量/称重条件（如「早上空腹」）写进记录并升该字段置信度；首次出现「条件明确」的
  体重读数时，同时写入 `profile.md` 与 `nutrition-goals.md` 作为**趋势锚点**（固定条件连续称 3–7 天取均值，
  用 2–4 周均值判方向，历史条件不明的单点不与之逐日比较）。

## 交付前的自检

1. 新增文件存在且路径符合约定；原图/原件已存 `raw/` 并带日期名。
2. 当日累计已用当次全部笔数重算，目标对比用的是**用户/医生给定**的目标；无目标就只报总数并声明无个体化目标。
3. `index.md` 与 `log.md` 都已更新，页数/产品数是**数出来的**而不是估的。
4. 记录里三件事分开：用户陈述、文档/标签转录、Agent 推算（含置信度）。
5. 报告给用户时说明「改动了哪些文件」，并列出仍待确认项（1–3 条，带会影响什么）。
